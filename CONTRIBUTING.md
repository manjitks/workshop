# Contributing to Open Workshop

The first local workspace is implemented; read `docs/PHASE_1.md` for scope. Contributions to engineering evidence, accessibility, practical build instructions, and documentation are as valuable as code.

## Start here

Read `CONTEXT.md`, `VISION.md`, and `AGENTS.md`. Choose a bounded task from the next implementation steps. For a new architecture, model, or hardware family, explain the proposed behavior, evidence, and maintenance burden before implementing it.

## Contribution workflow

1. Describe the problem, intended users, and acceptance criteria.
2. Identify relevant upstream tools and confirm license compatibility before copying material.
3. Implement the smallest complete change, including failure and unsupported states.
4. Run relevant verification and record exact results and limitations.
5. Update documentation and shared context when behavior or status changes.
6. Submit a focused change for maintainer review. Do not include credentials, private addresses, or device-specific secrets.

AI-assisted contributions follow the same rules. The submitting contributor remains responsible for correctness, provenance, licenses, and reviewability. Cite actual reference material; generated explanations are not scientific evidence.

## Required change description

- Problem and resulting behavior.
- Scope and explicitly unsupported cases.
- Verification performed and observed results.
- Scientific sources, assumptions, and applicable conditions when relevant.
- Privacy, permission, or migration changes when relevant.
- Screenshots or a short interaction description for UI changes.

## Community expectations

Be respectful, precise, and patient. Critique ideas and evidence rather than people. Welcome beginners and explain unfamiliar terms. Never pressure contributors to disclose personal information. Credit original work and report uncertainty honestly.

## Project setup still pending

A public repository, license, maintainer roster, branch protection, and private security-reporting channel have not been established. A CI workflow is defined but has not run on a hosted runner. These are required before a public contribution launch. Do not post secrets or exploitable vulnerability details in public discussions; a private reporting route must be established first.
